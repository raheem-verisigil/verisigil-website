Evaluation design

Small enough to start. Specific enough to learn.

The evaluation is deliberately bounded so that both sides can determine technical fit and commercial value without exposing production systems or proprietary architecture.

14 DAYSEvaluation window, starting after access and scope confirmation.
ONE WORKFLOWOne defined consequential action and declared test surface.
NO CARD REQUIREDNo automatic billing or charge when the evaluation ends.

Included in the free evaluation

  • Scope review and evaluation plan.
  • Access to the approved developer test path, subject to provisioning.
  • Synthetic or non-production test data only.
  • One API integration path and bounded test volume.
  • Review of observed outcomes and evidence limits.

Not included

  • Live-money transactions or production credentials.
  • Unrestricted API access or unlimited usage.
  • Unreviewed framework plugins or production adapters.
  • Source-code access or disclosure of protected architecture.
  • Production service levels, certification or compliance guarantees.
Integration note: The documented REST API is the initial evaluation route. Framework-specific plugins and SDK adapters are enabled only after compatibility and security checks; they are not represented as generally available marketplace products.
After the evaluation

A commercial decision—not an automatic subscription.

At the end of the 14-day window, both sides review the results. If the workflow demonstrates a credible business need, the next step is a separately scoped paid independent assessment or controlled enterprise pilot. Pricing, delivery responsibilities, data handling and acceptance criteria are agreed in writing before paid work begins. If there is no fit, the evaluation closes without an automatic charge.
