Quickstart · Local reproduction

Reproduce the current bounded test suite.

These instructions use synthetic values and the isolated evaluation branch. They do not call production and do not establish production readiness.

Never use production credentials or customer data. The current Terry scenario uses synthetic fixtures and a fake in-memory receipt store.

1. Select the evaluation revision

Branch: security/terry-fail-closed-execution-20261113
Commit: dfa626d309cf397f4e861a3449f258dcb6b5fdf5

git clone https://github.com/raheem-verisigil/verisigil-api.git
cd verisigil-api
git fetch origin security/terry-fail-closed-execution-20261113
git checkout dfa626d309cf397f4e861a3449f258dcb6b5fdf5

2. Install dependencies

python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt

3. Set synthetic test-only values

export DEPLOY_ENV=test
export SUPABASE_URL=http://127.0.0.1:1
export SUPABASE_KEY=verisigil-test-only-not-a-credential
export VERISIGIL_API_KEY=verisigil-test-api-key-only
export SIGN_SECRET=verisigil-test-signing-secret-not-for-deployment

4. Run focused and full tests

python -m compileall -q .
python -m unittest tests.test_proof_verification -v
python -m unittest tests.test_execution_authorization_fail_closed -v
python -m unittest tests.test_terry_validation -v
python -m unittest discover -s tests -v

Retain the Python version, exact commit, command, raw output and exit code. A test file existing is not a passing result.

5. Understand what the tests establish

The Terry scenario exercises synthetic authority revocation, contradictory capacity evidence, restoration, receipt verification and replay refusal. The receipt adapter is mocked in-memory. These tests do not prove live Supabase REST persistence, restart recovery, two-instance concurrency, source authenticity or downstream actuator enforcement.
