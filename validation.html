Architecture — Structural Enforcement

Provable Execution Integrity Layer

Based on consequence-custody-spec.md. Five distinct gaps — each addressed separately. No gap closes another.

✓
Gap 1 — Decision Correctness: f(policy, inputs) = output
Every deterministic policy decision records inputs hash, policy hash, output hash, and trace hash. Any third party can recompute. POST /v1/proof/correctness — honest scope: deterministic components only. ML/LLM reasoning paths explicitly excluded from this claim.
SCOPED
✓
Gap 2 — Non-bypassable Custody: Authorization Object architecture
The actuator requires a valid, single-use Authorization Object as a structural precondition — not a checked field, a missing capability. POST /v1/ao/issue → POST /v1/ao/verify. Bypass test at POST /v1/verify/bypass-test — every attempt returns HALT.
BUILT
✓
Gap 3 — Replay prevention: single-use nonce ledger
Every AO contains a nonce. Consumption adds it to the ledger. Re-presentation returns ALREADY_CONSUMED. POST /v1/verify/replay-test — attempt replay against consumed AO. GET /v1/ao/nonce — nonce ledger public.
BUILT
✓
Gap 4 — State freshness: AO bound to Hash(State) at authorization
State committed at authorization time. If authority is revoked, budget exhausted, or any declared field changes before execution — state hash mismatch — AO invalid. POST /v1/state/commit → POST /v1/state/verify. Conformance vector CV-005.
BUILT
✓
Gap 5 — Payload continuity: hop-by-hop hash verification
Authorized payload hash sealed at gate. Every system that touches it records a hop. Modification at any hop produces hash mismatch → HALT. POST /v1/continuity/payload → POST /v1/continuity/hop. Conformance vector CV-006.
BUILT
~
Gap 5 Reality — Closed-loop consequence verification
The downstream system confirms what actually happened back to VeriSigil. Not VeriSigil asserting — the actuator confirming. POST /v1/consequence/close. Honest gap: depends on downstream system being independently queryable. Not all action types support this yet.
PARTIAL
