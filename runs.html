FINDING-R3-001 · SEVERITY: HIGH · STATUS: CLOSED · CONFIRMED 2026-08-07
CV-003 Deviation — HIGH irreversible + human present returns ALLOW instead of ESCALATE
Conformance vector CV-003: HIGH consequence, transfer_funds, human_present=true, irreversible=true. Expected: ESCALATE. Actual: ALLOW. Reconfirmed twice by reviewer. Consistent. Root cause: engine treated human presence as sufficient to ALLOW rather than route to escalation. Human presence should strengthen governance, not weaken it. A present human means there is someone to escalate to — not a reason to bypass escalation. Control test (human_present=false) correctly returned DENY. The distinction between ALLOW and ESCALATE for human-present HIGH irreversible actions was not implemented.
→ CLOSED. Independently confirmed by Alkama Eqbal 2026-08-07: HIGH+irrev+human_present=true returns ESCALATE with HIGH_IRREVERSIBLE_ESCALATE signal. human_present=false control returns DENY. Both directions verified.
FINDING-R3-002 · SEVERITY: MINOR · STATUS: RESOLVED — CHG-011
Auth discrepancy / regression — verify/kit returned 500 after no-auth change
Run 3 found verify/kit and verify/conformance returning 401. A prior fix removed the auth requirement but introduced a regression: verify/kit started returning 500 (NameError — stale require_api_key call on undefined variables). Found by Alkama in post-deploy validation Run 3b. CHG-011 deployed: stale call removed. Both endpoints now return HTTP 200 with no key required. Independently revalidated before messaging Alkama.

FINDING-R3-003 · SEVERITY: NOTE · STATUS: RESOLVED — CHG-010
CV-005 — UNMODIFIED state returned STATE_CHANGED (field name mismatch)
Root cause identified by Alkama from the state_hash value: 44136fa355b3678a1146ad16f7e8649e94fb4fc21fe77e8310c060f61caaff8a is the SHA256 of an empty JSON object. state_verify was reading current_state_fields but callers sent state_fields (same field name as commit). current_fields was always {} — so every verify returned STATE_CHANGED regardless of actual state. Not a harness issue. A real engine bug. Fixed in CHG-010: state_verify now accepts state_fields OR current_state_fields.
→ CLOSED. Independently confirmed by Alkama Eqbal 2026-08-07: commit then verify unchanged fields returns FRESH with PROCEED. Verify modified fields returns STATE_CHANGED with HALT. Matches expected behaviour exactly.
