Execution control infrastructure · Current architecture

The runtime control point between AI intent and external effect.

VeriSigil evaluates a specific action at a declared execution boundary, checks the required authority and conditions, binds the decision to the exact parameters and records the result.

Current phase: PROVE. This page replaces earlier broad architecture material. No claim is made here of 3,497-state TLA+ verification, Z3 UNSAT proofs, Dilithium-3 signing, universal coverage or production-wide actuator enforcement.

Current reference path

  1. Receive a proposal and the state/authority context relevant to the protected workflow.
  2. Revalidate the proposal and create a signed validation receipt.
  3. Before execution, verify receipt integrity and proposal binding.
  4. Atomically consume the one-time receipt before issuing a short-lived authorization.
  5. Refuse when required evidence is missing, mismatched, stale or already consumed.

Open proof gates

  • API-to-Supabase receipt create/read/consume round-trip.
  • Independent process restart recovery.
  • Two-instance replay concurrency.
  • Durable authority/state registries and live authority re-derivation.
  • Downstream actuator integration with an observable side effect.
